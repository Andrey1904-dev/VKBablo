## План изменений (Этапы 2–10 ТЗ)

1. **Убрать Cloudflare**: удалить `wrangler.toml`, `server/worker.ts`, `bindWorkerEnv`, упоминания в документации. Локальный Node API остаётся как *локальный стенд разработки* (не production).
2. **Изоморфное ядро** `shared/*`: хэш версии, московское время, расписание, правила сообществ, движок контента, похожесть, гейт одобрения. Один код для frontend, Edge Functions и локального API.
3. **База**: миграции Supabase на 21 сущность из ТЗ, ограничения целостности, триггер сброса одобрения, RLS, RPC-функции с серверной проверкой прав, Storage-политики, Realtime, Cron (`pg_cron` + `pg_net`).
4. **Edge Functions**: `vk-ai-api` (вся клиентская серверная логика, проверка JWT) и `vk-ai-worker` (очереди генерации/публикации/статистики, идемпотентность, ретраи, dry-run).
5. **Frontend**: слой данных с тремя реализациями — `supabase` (production), `local` (локальный стенд), `demo` (полностью в браузере, для GitHub Pages без ключей). Дизайн, страницы и навигация сохраняются.
6. **GitHub Pages**: `base` path, hash-роутинг, workflow сборки/деплоя, проверки перед публикацией.
7. **Документация**: `CODEX_SETUP.md`, `docs/*`, `.env.example`, отчёт.
8. **Проверки**: typecheck, unit/integration-тесты, проверка миграций и отсутствия секретов, сборка, мобильная адаптивность, откат.

## Явные ограничения (честно)

- Реальные ключи (Supabase, VK, AI) **не подключены** и не запрашиваются.
- Реальные публикации VK запрещены: `app_mode = test` + `real_publish_enabled = false`.
- Облачные интеграции не считаются проверенными, пока не запущен реальный проект Supabase (см. «Непроверенное» в `docs/TESTING.md`).
- Внешность персонажей не выдумывается: описания в сиде помечены как `placeholder` до загрузки утверждённых референсов.
