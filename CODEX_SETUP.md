# VKBablo — подключение через Codex (MacBook Air M4)

> ВАЖНО: по умолчанию всё работает в демо-режиме. Не включайте реальные VK-публикации или платные AI API, пока не проверены авторизация, RLS, одобрение версии поста и защита от дублей.

## 1. Проверка исходников

```bash
git clone https://github.com/Andrey1904-dev/VKBablo.git
cd VKBablo
npm ci
npm run typecheck
npm test
npm run build
```

Для работы Codex используйте существующий проект и сверяйтесь с `HANDOFF.md`. Не добавляйте секреты в коммиты, чаты или клиентский код.

## 2. Supabase

1. Создайте или выберите проект Supabase в панели управления.
2. Установите Supabase CLI по официальной инструкции для macOS и выполните `supabase login` интерактивно.
3. Попросите Codex изучить `supabase/migrations` (включая RLS), `supabase/functions` и документацию проекта **до** применения миграций. Не выполняйте миграции вслепую в production.
4. Свяжите локальный проект командой `supabase link --project-ref <PROJECT_REF>`; идентификатор берите из настроек Supabase.
5. Проверьте миграции на тестовом проекте, затем примените к целевому проекту командой `supabase db push` после просмотра diff и подтверждения.
6. Разверните Edge Functions из `supabase/functions` по инструкциям CLI; настройте необходимые серверные секреты через `supabase secrets set` интерактивно на своём Mac, без записи значений в Git.
7. Настройте Supabase Auth, приватные Storage buckets, RLS и проверку прав владельца. **Особенно проверьте безопасное создание первого владельца до открытия сайта публично.**
8. Проверьте pg_cron/pg_net и фоновые задачи на тестовом проекте. Никогда не активируйте публикацию без одобрения.

## 3. GitHub Pages

В настройках GitHub: Settings → Pages → Source: GitHub Actions. Workflow `.github/workflows/pages.yml` публикует **демо-версию** на `https://andrey1904-dev.github.io/VKBablo/` после push в main. По умолчанию маршруты используют HashRouter; для сервера с поддержкой SPA можно задать `VITE_USE_HASH_ROUTER=false`. Пока нет реальных ключей, демо не может публиковать в VK.

Для Supabase production frontend потребуется отдельная конфигурация `VITE_BACKEND_MODE=supabase`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (публичный publishable/anon key), защищённые переменные сборки и повторная проверка RLS. **Не добавляйте service role, VK или AI токены в VITE_ переменные.**

## 4. Подключение VK и AI

Через Codex настройте серверные секреты Supabase Edge Functions; не вставляйте токены в веб-формы, если они не гарантируют серверное хранение. Проверьте права токенов VK, тестовую загрузку изображений и проверку отложенной публикации **без отправки реального поста**. Платные AI API включайте только после согласования расходов.

## 5. Контрольный список перед запуском

- [ ] Supabase Auth и RLS проверены с аккаунтом владельца и неавторизованным пользователем.
- [ ] Первый владелец не может быть захвачен посторонним.
- [ ] Изменение текста/изображения/сообщества/времени сбрасывает одобрение.
- [ ] Неодобренные и просроченные посты не публикуются.
- [ ] Повторный запуск воркера не создаёт дублей.
- [ ] Глобальный флаг реальной публикации выключен до явного разрешения.
- [ ] 13:30, 17:30, 21:30 отображаются по Europe/Moscow.
- [ ] Секреты не попали в GitHub, логи, сборку и историю коммитов.
